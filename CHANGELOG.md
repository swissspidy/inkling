# @swissspidy/inkling

## 0.1.0

### Minor Changes

- [#5](https://github.com/swissspidy/inkling/pull/5) [`9bbda40`](https://github.com/swissspidy/inkling/commit/9bbda40a94e8a71747cb96e55e959663d99c1707) Thanks [@swissspidy](https://github.com/swissspidy)! - Astro integration: `@swissspidy/inkling/astro` builds the catalog from the pages `astro build` emitted (selected with `include`, `exclude` and `page`, or replaced with `items`), writes `manifest.json` and the shards into the build output with an incremental embedding cache in `node_modules/.cache/inkling`, and loads the web components on every page with the manifest preset. The components now take their manifest from `window.InklingConfig.manifest` when they have no `manifest` attribute, and the ES module build of the components applies `window.InklingConfig` too.

- [#15](https://github.com/swissspidy/inkling/pull/15) [`6ccd987`](https://github.com/swissspidy/inkling/commit/6ccd987feceaf5d3abfec9652255c2472bc42c13) Thanks [@swissspidy](https://github.com/swissspidy)! - Format version 2 ([ADR 0011](https://github.com/swissspidy/inkling/blob/main/docs/adr/0011-format-v2-columns.md)): shards list the item ids in a small JSON header, keep each item's prior, publication time and section in binary columns, and the rest of its metadata (title, URL, tags, date, image) as separate JSON that the client decodes only for the items a call returns. Loading 100,000 items in Chromium takes about a third less main-thread time, the JS heap after loading is 85% smaller (33 MB → 5 MB), and recency no longer depends on how the visitor's browser parses dates. `inkling build`, the Astro integration and the WordPress plugin now write version 2 (manifest `formatVersion: 2`). The client reads versions 1 and 2. A page still running an older client refuses a version 2 manifest and keeps its server-rendered fallback until its script is updated, so upgrade the client before rebuilding. `decodeShard()` from `@swissspidy/inkling/format` returns the columns (`ids`, `prior`, `time`, `sections`, `section`), `count`, `version` and `item(i)`, alongside `items`.

- [#1](https://github.com/swissspidy/inkling/pull/1) [`5ea1be8`](https://github.com/swissspidy/inkling/commit/5ea1be831de9f06bfba776e9db93a14451d87f70) Thanks [@swissspidy](https://github.com/swissspidy)! - First release (milestone 1): `inkling build` embeds a catalog from JSON, RSS/Atom, a sitemap or a loader module with EmbeddingGemma (or a pluggable provider) into `manifest.json` and int8 vector shards, incrementally. The dependency-free client ranks related items in the browser with `const inkling = await Inkling.load({ manifest })` and `await inkling.related(id)`, and `<inkling-related>` fills server-rendered slots with them without layout shift.

- [#1](https://github.com/swissspidy/inkling/pull/1) [`5ea1be8`](https://github.com/swissspidy/inkling/commit/5ea1be831de9f06bfba776e9db93a14451d87f70) Thanks [@swissspidy](https://github.com/swissspidy)! - Personalization (milestone 2): with the site's consent hook (`consent`, `Inkling.configure()` or `window.InklingConfig`), the client records view, click, dwell, follow and hide signals in IndexedDB, derives a profile from them on every page, and ranks "for you" with `recommend()` and `rank()`. `explain()` and every result's `why.because` say which of the visitor's items a recommendation leans on. `pause()`, `resume()`, `export()` and `forget()` are the visitor's controls. New components: `<inkling-for-you>` and `<inkling-page>`.

- [#12](https://github.com/swissspidy/inkling/pull/12) [`49514d5`](https://github.com/swissspidy/inkling/commit/49514d5f572f01d2fe7c38d6280da31229a56bf9) Thanks [@swissspidy](https://github.com/swissspidy)! - EmbeddingGemma's q4 weights now load `model_no_gather_q4`, the q4 file browsers can run. `model_q4` needs an ONNX Runtime operator (`GatherBlockQuantized`) that browsers lack, so `createQueryEmbedder(manifest, { dtype: 'q4' })` failed in browsers. The manifest names the file in an optional `model.file` field, and it is part of the space and the embedding-cache key, so a catalog built with `--dtype q4` before this release is re-embedded (q8 catalogs are unchanged).

- [#4](https://github.com/swissspidy/inkling/pull/4) [`c2fe6e5`](https://github.com/swissspidy/inkling/commit/c2fe6e5ce6373c46ee7d8ab6f8dee2fbdeef8e82) Thanks [@swissspidy](https://github.com/swissspidy)! - Free-text search on the device: the build publishes the model's query prompt (`model.queryPrompt`), `inkling.search(vector, options)` ranks the catalog against a query vector (optionally blended with the profile), and `@swissspidy/inkling/query` embeds the query in the browser with the catalog's own pinned model through Transformers.js (or in plain JavaScript for `hash` catalogs). The query text never leaves the device.

- [#13](https://github.com/swissspidy/inkling/pull/13) [`fcdb4e5`](https://github.com/swissspidy/inkling/commit/fcdb4e54d93a3b271dfbee445512c50441da5b66) Thanks [@swissspidy](https://github.com/swissspidy)! - Ranking is about 11× faster in Node and 5× faster in a throttled browser on a 100,000-item catalog (ADR 0010). The client keeps the loaded catalog as columns (one contiguous block of vectors, and typed arrays for norms, priors, dates and sections) and computes similarities with a 332-byte WebAssembly SIMD kernel that splits the query into two int16 vectors and sums exactly in integers. Results match the previous release to within 1e-8. Where WebAssembly SIMD is unavailable (older browsers, a Content Security Policy without `'wasm-unsafe-eval'`) or the catalog is float32, a JavaScript kernel gives the same results. New: `Inkling.load({ kernel: 'js' })` forces it, and `inkling.kernel` says which one runs.

- [#3](https://github.com/swissspidy/inkling/pull/3) [`1b9b703`](https://github.com/swissspidy/inkling/commit/1b9b7034d3d141472b1b87a0fab57395f0c92b4c) Thanks [@swissspidy](https://github.com/swissspidy)! - "Since your last visit": the client records visits with consent (`visit()`; a visit ends after `visitGapMinutes` without activity), and `sinceLastVisit()` ranks the items published since the previous one. `recommend()` accepts `after`. The new `<inkling-digest>` component fills server-rendered slots with them, and adds a one-line summary from the browser's built-in Summarizer where its on-device model is available. The Summarizer helpers are in `@swissspidy/inkling/digest`.

### Patch Changes

- [#7](https://github.com/swissspidy/inkling/pull/7) [`2b082bb`](https://github.com/swissspidy/inkling/commit/2b082bb5769d44b19aa667b1a3ce03b0e813763a) Thanks [@swissspidy](https://github.com/swissspidy)! - Every public export has a doc comment, and the API reference is generated from them and published with the demo at https://swissspidy.github.io/inkling/api/. The types that public signatures already used are now exported too: `RankingOptions` (from `@swissspidy/inkling`), `SitemapOptions` (from `/build`) and `TransformersModel`, `TransformersTokenizer` and `TransformersTensor` (from `/query`).

- [#6](https://github.com/swissspidy/inkling/pull/6) [`e8d6684`](https://github.com/swissspidy/inkling/commit/e8d6684582ab18383ec3c82b7ccf5ac5c0821b73) Thanks [@swissspidy](https://github.com/swissspidy)! - Large catalogs no longer block input while they load and rank: the client scores candidates in short slices and yields to the page between them (with `scheduler.yield()` where the browser has it, otherwise a new task), and decodes each shard in a task of its own. Results are unchanged, except that items with exactly equal scores now always come in manifest order instead of the order their shards arrived in. Ranking is also faster, because only the best candidates are kept in order instead of sorting all of them. No API or option changes (ADR 0008).

- [#7](https://github.com/swissspidy/inkling/pull/7) [`2b082bb`](https://github.com/swissspidy/inkling/commit/2b082bb5769d44b19aa667b1a3ce03b0e813763a) Thanks [@swissspidy](https://github.com/swissspidy)! - The list components no longer drop keyboard focus: while a slot holds focus, `<inkling-related>`, `<inkling-for-you>` and `<inkling-digest>` wait for it to leave before replacing the slots. An `aria-label` on a slot or its link that contains the fallback item's title now gets the new item's title, so the link's accessible name matches what it shows.

- [#7](https://github.com/swissspidy/inkling/pull/7) [`2b082bb`](https://github.com/swissspidy/inkling/commit/2b082bb5769d44b19aa667b1a3ce03b0e813763a) Thanks [@swissspidy](https://github.com/swissspidy)! - Signals of a kind the client doesn't know (written by a newer release) are no longer counted as views or pruned by age: they are kept as they are and ignored (ADR 0009).
